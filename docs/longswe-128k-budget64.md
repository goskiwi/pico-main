# LongSWE-Bench：64 轮预算完整重跑

沿用上一轮的三个官方 128K 档任务、原始提交、源码上下文、模型、工具、压缩参数与原始验收节点；两组统一改为最多 **64 个主模型轮次、每任务 1,800 秒**。全部从未修复的原始提交重新开始，非续跑旧补丁。

模型：`gpt-5.6-luna`；接口：`https://2btocken.xyz/v1/responses`。密钥仅通过环境传入。此次未修改 Pico 生产代码；实验脚本的预算已改成显式参数，并使用独立 `budget64` 目录。

工具调用从 18 增至 21，输出 Token 也增加。输入减少不等于所有效率指标同时改善。

## 与上一轮的关系

上一轮 12 轮预算结果完整保留在各任务的 `raw/`、`managed/`，汇总仍是 `summary.json`。本轮在各任务 `budget64/raw/`、`budget64/managed/`，汇总是 `summary-budget64.json`。

本轮仍是每任务每条件一次。模型生成存在随机性，且实际均在 12 轮以内完成；不能把两轮结果差异全部归因于提高上限，也不把两轮混成一份稳定收益。旧轮 pytest managed 的截断问题已通过这次充足预算的完整重跑排除。

## 数据与环境限定

继续使用官方 **128K 档**，三个条目标注分别为 123,833、95,356、79,694 Token；模型硬窗口为 272,000，不能写成每条都输入恰好 128K 或模型窗口只有 128K。

验收环境仍为本地 macOS、独立 Python 3.10，执行原始 test_patch 的 FAIL_TO_PASS 与 PASS_TO_PASS 节点，不是官方 Docker harness。参考补丁和隐藏测试仍未提供给修复模型。

原始证据位于项目 `.pico/benchmarks/longswe/`。每次运行包含 `specification.json`（实际预算）、`requests.json`（逐轮用量和原文检查）、`outcome.json`、`result.json`、`model.patch`、独立验收结果与 Session/Trace。

复现入口现在显式接受：`--run-name NAME --max-turns 64 --max-seconds 1800`。新实验应选择新的 NAME，不覆盖这轮记录。
