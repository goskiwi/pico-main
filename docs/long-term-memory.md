# Pico 项目长期记忆

显式开启：`pico --memory`，或在项目配置中设置 `PICO_MEMORY=1`。
API 使用 `PicoConfig(memory_enabled=True)`。默认关闭，避免未经启用保存跨任务信息或发起额外模型调用。
API 调用方退出时应调用 `Pico.close()`；CLI 已统一处理。

## 结构与职责

```text
.pico/memory/
├── topics/*.md       主题记忆，JSON frontmatter + Markdown 正文
├── processing.json   已处理来源、显式请求、失败退避、待应用方案、删除记录
└── worker.lock       本项目 Pico 写入者之间的文件锁
```

四种类型：`user` 用户背景与偏好、`feedback` 工作方式及原因、`project` 无法从代码直接获得的背景／决策、`reference` 外部参考位置。
不保存临时任务进度、一次测试结果、代码／Git 可直接推导的事实或 AGENTS.md 已有规则。
这与当前 Run 的 Compaction 和 Checkpoint 分工不同：长期记忆用于新 Run，后两者用于原任务续接与恢复。

每份主题记录名称、说明、类型、最近更新的来源 Session/Run 或显式请求、证据 Event ID 和来源时间。
正文可直接查看。格式严格，未兼容其他元数据格式；目录扫描实时生成，不另存 MEMORY.md。

## 后台更新

```text
启动／Run 结束／显式记住请求
→ 唤醒 Worker
→ 读取已完成且尚未处理的 Run 或显式请求
→ 独立模型读取目录、按需读已有记忆
→ 提出新增／更新／删除
→ 校验格式、路径、来源与既有主题的完整读取
→ 保存具体文件更新方案
→ 原子替换各主题文件
→ 记录处理成功
```

主 Agent 不执行自动提取。Worker 使用独立客户端与 Provider 会话，没有 Shell、源码写入或递归 Agent。
每次唤醒最多处理 3 个来源；每个来源最多 5 次模型请求、60 秒，输出最多 4,000 Token 且不超过调用方配置。
输入包含用户原文、已提交摘要、近期执行元数据与终答，不加载大工具正文。整体超预算明确失败，来源不标完成；不默默丢弃用户消息。
失败记录退避时间，下一次启动、Run 结束或显式请求时再检查；没有轮询或长期驻留的定时任务。
未完成、取消或停止的 Run 不自动提取；同项目其他 Session 的已完成 Run 可以成为来源。无法解析的旧 Session 被跳过并报告，不迁移。

同一项目只有一个提取写入者，管理更新也遵守同一锁。模型调用期间读取主任务无需等待写锁。
文件更新方案先落盘：若只应用了一部分就崩溃，重启重用同一方案和文件名，不重新生成一批主题。
单个文件原子替换；多个文件不是一个事务，读取者可能在应用期间看到部分新主题。
处理成功标记写入失败时，方案仍保留，可以幂等续接；不承诺模型提取恰好调用一次。

更新按引用证据的时间比较：旧来源不能覆盖同名主题的更新内容。
删除记录只保存文件名与时间，防止旧来源重建同名主题；之后新的明确请求仍能重新建立它。
语义重复、来源选择及内容是否值得记住仍由模型判断，不能宣称永不幻觉或百分之百语义去重。

## 使用与管理

新 Run 的模型输入包含前 10 个主题的有界目录，不自动注入全部正文。主 Agent 可调用：

- `list_memories(offset, limit)`：继续浏览目录，每页最多 10 项。
- `read_memory(filename, offset, limit)`：按字符偏移读取正文，每页最多 1,000 字符，并返回来源与下一页位置。

记忆是历史参考，不能覆盖当前用户要求、项目指令或 Runtime 权限。变化的事实应检查当前文件。
主 Agent 不得通过 Shell 或文件工具改记忆，也不能在后台完成前声称已保存或已忘记。

CLI 管理：

- `/memory list [OFFSET]`：分页查看目录。
- `/memory remember TEXT`：持久化显式请求，后台处理；可用于新增或纠正已有内容。
- `/memory forget FILE.md`：串行删除指定主题，不调用模型；只在 Agent Attempt 之间管理。
- `/memory status`：查看待处理请求、待应用方案、失败退避与来源错误。

`forget` 删除长期记忆主题，不擦除原 Session/Run 日志或当前对话中已经出现的文字。
Worker 是进程内后台线程；CLI 退出最多等待 5 秒，然后取消当前提取。若进程被强杀，下次启动补处理。
内部锁不保护外部编辑器；不要在提取更新中手工修改同一主题。

## 验证

确定性协议测试：`uv run python -m unittest tests.test_memory -v`。
真实模型测试：`PICO_MEMORY_LLM_TEST=1 uv run python -m unittest tests.test_memory_llm -v`，需要项目 Responses API 配置。
真实测试在临时工作区执行后台记住、独立 Session 回读、纠正原主题、删除和重启确认，不修改当前项目记忆。
