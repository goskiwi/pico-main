# 可选复现检查接口

程序化构造 `Pico(..., check_runner=...)` 可以安装 `run_check`。执行器由调用方提供；默认 CLI
没有此工具，也不附带 Docker 判分后端。Core 不依赖 Docker。

执行器必须是受信任、具备隔离能力的应用依赖。传入普通宿主 Python／Shell 函数不会使它变成
沙箱；不能用文件工具的路径检查来描述任意代码执行的隔离保证。

模型可以提交最多 16,000 字符的 Python 或 pytest 片段，申请 1～60 秒的执行时间，实际时间仍
受当前 Run 的剩余预算限制。执行器负责隔离、资源限制、输出限制和清理。Pico 负责工具准入、
事务记录与结果回写，不把可调用对象的存在当作隔离已经实现的证明。

与面试主线对应的边界由 `tests/test_checks.py` 验证：

- Ask 不暴露执行工具，未配置执行器时也不安装工具。
- 非法参数在执行前被拒绝，执行不能混入只读 Observation Batch。
- 执行失败进入 RunLog，执行器接收当前请求的 Deadline。
- 模型自行设计的检查通过，不替代 CompletionController 的固定验证，也不能绕过验证失败。

外部仓库题库、Docker 判分及其集成测试已移除。此处只说明保留的扩展接口与 Runtime 边界，
不声称仓库仍提供容器执行后端。
