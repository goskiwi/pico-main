# 编辑观察与验证反馈重构

## 职责

模型提出修改，不携带文件版本凭据。`edit_file` 参数只接受 `path / old_text / new_text`，旧 `expected_revision` 参数由严格 schema 拒绝；没有短 ID 替代或双接口兼容。

ToolRuntime 使用当前请求内成功读取或成功修改收据产生的内部版本。编辑审批前绑定该版本，进入修改服务时在锁内比较实际文件，提交时继续保留原有版本复验、前像和原子发布。新请求或恢复后必须重新读取，不把当前磁盘状态自动当成模型已经观察的状态。

`VerificationService` 从完成控制器中抽出，统一项目验收发现、固定命令执行、审批、前后工作区观察和最终复查。中途 `verify` 无模型参数，仅运行 Runtime 已发现的验收；最终 `submit_final` 再次执行同一验收，不能用中途通过绕过最终检查。后续修改会使通过状态过期。

普通项目使用 `code` 模式的审批命令工具选择和执行测试；受限模式继续禁止任意命令，但可开放固定 `verify`。Ask 和只读 Delegate 不修改工作区，完成时不要求运行项目验收。没有增加自动测试调度或阶段状态机。没有独立验收配置时，写任务明确声明未经过独立验收；既有强制验收要求继续生效，诊断命令意外修改仓库后也不能走无验收完成路径。

较长验证输出保存全文，反馈保留首尾并提供 artifact ID，模型可通过现有 `read_artifact` 分页获取。执行器自身的输出上限仍生效，并在记录中标明。
