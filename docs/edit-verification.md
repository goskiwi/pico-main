# 编辑观察与验证反馈重构

## 职责

模型提出修改，不携带文件版本凭据。`edit_file` 参数只接受 `path / old_text / new_text`，旧 `expected_revision` 参数由严格 schema 拒绝；没有短 ID 替代或双接口兼容。

ToolRuntime 使用当前请求内成功读取或成功修改收据产生的内部版本。编辑审批前绑定该版本，进入修改服务时在锁内比较实际文件，提交时继续保留原有版本复验、前像和原子发布。新请求或恢复后必须重新读取，不把当前磁盘状态自动当成模型已经观察的状态。

`VerificationService` 从完成控制器中抽出，统一配置命令的执行、审批、前后工作区观察和最终复查。中途 `verify` 无模型参数，仅运行已有配置；最终 `submit_final` 再次执行同一验收，不能用中途通过绕过最终检查。后续修改会使通过状态过期。

普通项目使用 `code` 模式的审批命令工具选择和执行测试；受限模式继续禁止任意命令，但可开放固定 `verify`。没有增加自动测试调度或阶段状态机。没有独立验收配置时，普通完成明确声明未经过独立验收；既有强制验收要求继续生效，诊断命令意外修改仓库后也不能走无验收完成路径。

较长验证输出保存全文，反馈保留首尾并提供 artifact ID，模型可通过现有 `read_artifact` 分页获取。执行器自身的输出上限仍生效，并在记录中标明。

## 检查

34 项 Runtime 边界检查通过（原 20 项加 14 项），覆盖旧参数拒绝、读前编辑拒绝、外部修改、审批期间漂移、连续修改、受限模式固定验证、权限撤回、失败—修复—重测—最终验收、验证过期、无独立验收说明、输出取回、验证中断恢复、验收记录保存后的漂移和验证命令副作用。9 项 RepoMap 导航检查通过。编译与差异格式检查通过。

## 真实 Jinja 对照

从与上一轮相同的修复前提交启动两组新运行，目录为 `.pico/benchmarks/jinja-async/pallets__jinja-1960/feedback-v2/{without_map,with_map}/`。每组 64 轮、1,800 秒，仅组间 RepoMap 开关不同；两组均开放固定 verify。原始验收仍各为 9 failed、115 passed。

用量不完整：无地图组 27 次逻辑请求对应 28 次 HTTP 尝试，有地图组 45 次对应 48 次尝试，且最后请求没有返回用量。已知 Token 仅为后端已返回部分，不报告精确完整成本收益。原始请求和工具调用配对检查均通过。

实验结束后的最终复查还调整了两个安全记账点：最终验收反馈必须在最后一次工作区复查之前保存；固定验收命令造成的副作用必须反映到工具结果。均添加定向检查并通过，未在真实运行期间修改生产代码。最终代码另存 `runtime-source-feedback-v2-final.tar.gz`；上述真实模型数字对应实验归档版本，不冒充再次完整重跑后的数字。
