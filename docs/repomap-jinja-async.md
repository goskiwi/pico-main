# Jinja 跨模块异步清理：RepoMap 对照

## 任务与口径

上游任务：[Jinja PR #1960](https://github.com/pallets/jinja/pull/1960)，关联异步生成器资源清理问题 #1953、#1955、#1956。这是本地适配的上游任务，不称为官方 LongSWE-Bench 成绩。

修复前提交 `079e8312c3ceee54066d2dc887da83867f2db68a`，上游合并提交 `1655128cfc0e8b598d5b3f361a3983f82098276b`。任务描述按行为综合上述问题：流式异步渲染提前停止时，关闭应传播到内部生成器，并考虑 block、include、继承、循环和异步过滤器。明确披露这是综合任务描述，不是未经改写的原始 issue；模型未获得生产文件路径、内部函数名或参考补丁。

两组独立从修复前提交开始，同一模型 `gpt-5.6-luna`，同一接口和工具，仅 RepoMap 开关不同。每组一次，最多 64 轮、1,800 秒；无额外代码语料注入，关闭记忆、委派和上下文压缩。输入使用后端累计 input_tokens，包含地图和缓存 Token，不是每轮平均输入。测试失败反馈会提供给模型，初始隐藏测试不放入模型工作目录。

## 验收可靠性

使用上游补丁中的 `tests/test_async.py`、`tests/test_async_filters.py`，不增加自定义回归，不改写断言。Python 3.10、pytest 7.4.0、Trio 0.22.2、MarkupSafe 2.1.5，本地环境运行。

两组修复前均为 **9 failed, 115 passed**。失败涉及循环错误、基本流式生成、include、block、继承和异步过滤器；清理产生的 ResourceWarning 被上游 warning-as-error 设置判失败，外层可显示为 PluggyTeardownRaisedWarning。在相同环境对上游修复提交独立检查，**124 passed**，确认不是依赖环境本身导致失败。未放宽警告处理。

## 结果

两组均在 1,800 秒达到总时间预算，以 `stopped / deadline_exceeded` 结束，均未调用最终提交触发 Runtime 验收。结束后对各自最终磁盘补丁独立验收，两组均失败。

| 指标 | 无 RepoMap | 有 RepoMap |
| --- | ---: | ---: |
| 模型请求轮次（含最后未返回请求） | 54 | 28 |
| 工具调用 | 69 | 83 |
| 读取、搜索、列目录调用 | 54 | 67 |
| 已知累计输入 Token | 1,894,000 | 1,285,735 |
| 独立验收通过 | 115 | 109 |
| 独立验收失败 | 9 | 15 |
| 版本凭据拒绝 | 12 | 4 |

有地图组工具调用增加 **20.29%**。已知输入账面减少 **32.12%**，但这不是可用的成功任务节省指标：两组均未完成，且截止时均有请求没有返回用量；地图组 28 次逻辑请求发生 29 次 HTTP 尝试。两组 `usage_complete=false`，因此不能报告精确完整费用或完整输入减少比例。所有记录请求的当前任务原文和工具调用配对检查通过。

## 失败观察与结论

- 无地图组的 9 个原始失败仍存在。模型多次把返回版本字符串中的字符抄错，读后仍重复错误值，导致 12 次修改拒绝；这是真实工具交互开销，不是跨模块定位开销，不能直接归因为没有地图。
- 有地图组修改了 `async_utils.py`、`compiler.py`、`environment.py`、`runtime.py`，但原始 9 项失败仍存在，另有 6 项递归异步循环测试回归。跨模块修改本身不等于正确解决跨模块问题。
- 两组都保留了 `auto_aiter` 异步生成器包装，独立验收仍观察到其提前垃圾回收的 ResourceWarning。地图组另有一次无效搜索表达式错误。
- 有地图组生成 28 次地图，最大 1,009 Token；已读后大多数地图在约 400 Token。地图自身变小没有保证减少整个修复过程的工具调用。

结论：这是符合“不给内部入口、需要跨模块探索”的候选任务，但本次 **两组成功率均为 0/1**，不能用于证明 RepoMap 提效，也不能用于简历中的成功修复收益。实验同时暴露了版本凭据抄写、持续探索而迟迟未提交验收的问题；本轮没有中途修改 Pico、放宽安全检查、追加人工提示或调整验收来帮助某一组。下一步若改进工具交互或验证节奏，应作为新的实验条件，保留本轮失败记录，不覆盖数据。

## 证据位置

项目目录 `.pico/benchmarks/jinja-async/`；任务子目录 `pallets__jinja-1960/cross-module-v1/{without_map,with_map}/` 保存任务配置、请求与用量、地图、Session/Trace、模型补丁和修复前后验收。运行时源码保存为 `runtime-source-cross-module-v1.tar.gz`。一次任务的一对运行只能作为个案证据，不能推出通用节省百分比。
