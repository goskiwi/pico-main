## 初轮失败与修复

最初各场景出现重复读取，修复样例虽然已改正确，却没有正常进入 Runtime 完成验证。首次 repair 和 crash_resume 在轮数上限停止，其余仍重复读取的旧进程由验证人员中止。

检查发现两项模型输入问题：

1. Session 历史被包装为单条用户 JSON 消息，没有使用 Responses 原生角色和 function_call/function_call_output 配对。已改为原生消息列表，估算与发送共用同一结构。
2. 模型可见的 Runtime 工具权限清单漏掉 submit_final，与实际 Schema 不一致。仅修复消息格式后仍出现重复读取；补齐清单后，最终五个场景均完成。

初轮与中间轮没有被覆盖。不能将所有改善单独归因于某一项改动。

本地定向检查由 19 项扩展到 20 项，新增权限清单与 Schema 一致性检查，并加强实际请求中原生工具配对的检查；全部通过。静态检查和差异格式检查通过。
